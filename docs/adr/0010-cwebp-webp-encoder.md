# ADR-0010: Use cwebp as the explicit WebP derivative encoder

- Status: Accepted
- Date: 2026-09-27

## Context

Mediarama's initial image pipeline used ImageMagick for both image preparation and final WebP encoding.

The representative derivative-format benchmark exposed a production-relevant upstream regression in ImageMagick 6.9.12-98: different requested WebP quality values produced byte-for-byte-equivalent quality curves.

Upstream ImageMagick6 source history confirms the cause:

- commit `a0bd1722c7e79c81b68418cafed904df673c3f34` removed assignment of `image->quality` to `WebPConfig.quality` while adding near-lossless handling;
- tag `6.9.12-98` contains that behavior;
- commit `8f269831a20dddf992b3b9b787e3105f6272e573` restores `configure.quality=(float) image->quality`;
- the restored behavior is present in `6.9.13-1` and later.

A successful ImageMagick WebP encode therefore does not prove that the configured quality is honored on all supported deployment runtimes.

Mediarama needs a stable, testable quality boundary rather than a version-string exception for one known broken package.

## Decision

Mediarama uses the WebP project's `cwebp` utility as the explicit final encoder for WebP display derivatives.

The pipeline is:

1. ImageMagick reads the untrusted original under the existing finite resource envelope.
2. ImageMagick applies auto-orientation, metadata stripping and fit-inside resizing.
3. It writes a temporary lossless PNG.
4. Optional watermark composition is completed before final encoding and also produces a stripped lossless PNG.
5. `cwebp` receives only that bounded, Mediarama-generated PNG.
6. `cwebp -q <profile quality>` performs the one lossy WebP encode.
7. `cwebp` metadata copying is explicitly disabled.
8. Failure or absence of `cwebp` fails derivative generation instead of silently falling back to ImageMagick's WebP writer.

Runtime configuration:

- `CWEBP_BINARY`, default `cwebp`;
- `CWEBP_PROCESS_TIMEOUT_SECONDS`, default 60 seconds.

The encoder uses explicit `-m 4`, lossless alpha compression (`-alpha_q 100`) and `-metadata none`. The profile quality remains the product-level RGB quality value.

The image processing-version floor is incremented because changing the final encoder changes derivative bytes.

## Capability verification

CI installs the distribution's libwebp utilities and executes the production `CwebpEncoder`.

A deterministic integration fixture is encoded at materially different quality values. The gate requires:

- both results to be readable WebP;
- encoded bytes to differ;
- the high-quality result to be materially larger for the deterministic fixture;
- the prepared source checksum to remain unchanged.

The general derivative-format benchmark also routes WebP through the same `CwebpEncoder`, so benchmark evidence and production output no longer use different WebP backends.

## Security boundary

`cwebp` is not used as the first parser for uploaded/untrusted files.

Only ImageMagick, under Mediarama's existing resource and policy limits, reads the original. The cwebp input is a bounded, stripped PNG generated by Mediarama after decode and resize.

The cwebp subprocess has its own finite parent-process timeout. Maximum pixel dimensions are already bounded by the derivative profile before cwebp runs.

## Rejected alternatives

### Only reject ImageMagick 6.9.12-98 by version

Rejected as the primary solution.

A version check would block the known regression but would still couple WebP quality semantics to ImageMagick packaging and delegate behavior. Capability matters more than a version string.

### Pass another ImageMagick WebP define

Rejected.

The 6.9.12-98 source path does not assign the requested quality to `WebPConfig.quality`. A format define cannot safely be assumed to restore that missing assignment.

### Require ImageMagick 7 only

Rejected for now.

It would unnecessarily narrow deployments while Mediarama already needs ImageMagick for image preparation and can use the codec project's own stable encoder for the final WebP boundary.

### Silently fall back to ImageMagick WebP

Rejected.

A fallback could recreate the exact silent quality failure that triggered this decision. Missing/broken cwebp is an operational error and must fail closed.

## Consequences

Positive:

- WebP quality behavior is owned by a dedicated codec tool with explicit `-q` semantics;
- Ubuntu 24.04 can use its packaged `webp` utilities independently of the ImageMagick 6 wrapper regression;
- benchmark and production WebP paths are aligned;
- the original remains immutable and public derivatives remain metadata-stripped;
- future output codecs can be treated as explicit encoder capabilities rather than assumed ImageMagick extensions.

Costs:

- production workers now require the libwebp command-line utilities;
- WebP generation uses a lossless PNG handoff between ImageMagick and cwebp;
- operators must monitor both ImageMagick and cwebp runtime availability;
- changing cwebp behavior/version may require benchmark review and a processing-version bump when output semantics materially change.
